* Lab defaults

- LLM: =z-ai/glm-5.3-flash= through OpenRouter
- Search: =@brave/brave-search-mcp-server@2.1.3=
- Fetch: =mcp-server-fetch==2026.8.18=
- MCP transport: stdio
- Parallel harnesses: 4
- Case: =DR-001=
- Run outputs: =runs/<case>/<harness>/<run-id>/=

The default four-way matrix is:

| Harness | Controlled retrieval |
|---------+----------------------|
| StarIntel Auto Research CL | Brave+Fetch MCP bounded evidence prefetch; native MCP injection not exposed by current CL runtime |
| InternScience ResearchHarness | Brave+Fetch MCP as the only two network tools |
| GPT Researcher | custom retriever backed by Brave search + Fetch hydration |
| Hugging Face Open Deep Research / smolagents | managed search agent with only Brave+Fetch MCP tools |

Every lane receives the same =guidelines/auto-research.org= contract and case question.

* Dry-run matrix

This requires no credentials, no upstream checkout, and spends no API credits. It writes the exact per-lane plans.

#+begin_src sh
./bin/research-lab matrix \
  --case DR-001 \
  --parallel 4 \
  --model z-ai/glm-5.3-flash \
  --dry-run
#+end_src

* Run GLM-5.3-Flash matrix

#+begin_src sh
./bin/research-lab matrix \
  --case DR-001 \
  --parallel 4 \
  --model z-ai/glm-5.3-flash \
  --strict
#+end_src

Each lane gets its own Brave and Fetch stdio subprocess pair, so concurrent runs do not share MCP process state.

* Inspect latest results

#+begin_src sh
for harness in starintel researchharness gpt-researcher smolagents-odr; do
  latest="$(find "runs/DR-001/$harness" -mindepth 1 -maxdepth 1 -type d 2>/dev/null | sort | tail -n1)"
  printf '\n== %s ==\n' "$harness"
  if [ -n "$latest" ]; then
    jq '{status, duration_seconds, model, retrieval_mode}' "$latest/result.json"
    jq '{servers, used_tools}' "$latest/mcp.json"
  else
    echo '(no run yet)'
  fi
done
#+end_src

* Run layout

#+begin_example
runs/DR-001/<harness>/<run-id>/
  request.json
  command.json
  stdout.log
  stderr.log
  report.md
  result.json
  adapter-result.json
  mcp.json
  mcp-events.jsonl
  mcp-brave.stderr.log
  mcp-fetch.stderr.log
  traces/                 # when the upstream emits them
  workspace/              # when the upstream uses one
  native-artifacts/       # StarIntel native output capture
#+end_example

=mcp.json= records package versions, transport, advertised tools, and tools actually used. =mcp-events.jsonl= records search queries, fetched URLs, success/failure, counts, and durations. API keys are never written.

* Controlled network policy

For a controlled benchmark:

#+begin_example
LLM inference  -> OpenRouter
search         -> Brave Search MCP
page retrieval -> Fetch MCP
#+end_example

No adapter is permitted to silently select a different hosted search or scraping backend. A lane that cannot honor the contract must fail or explicitly identify a partial adaptation.

GPT Researcher also uses =openai/text-embedding-3-small= through OpenRouter for its internal vector-memory requirement. This is embedding work, not the reasoning/generation model under test; all reasoning/generation roles remain =z-ai/glm-5.3-flash=.

StarIntel is currently the one partial lane: the current CL runtime does not expose an MCP tool injection seam at benchmark launch, so the adapter performs Brave discovery + Fetch retrieval first and supplies that evidence to the native Auto Research loop. Its =adapter-result.json= marks =adaptive_mcp_tools=false= so it cannot be mistaken for equivalent native tool access.

* Test without spending credits
